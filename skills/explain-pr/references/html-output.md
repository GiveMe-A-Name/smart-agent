# 排版与 HTML 实现要求

## 信息层级

- 页面标题下首先展示一个独立的引言区块：先写“当前 PR 的一句话角色”，再写陌生 reviewer 进入问题所需的最小上下文。角色句可以加粗或使用强调色，整个区块字号略大于正文。
- 如果引言后的具体例子默认折叠，折叠块应紧跟引言，并用标题说明它具体化哪件事；不要让例子在视觉上取代引言主线。
- 后续章节沿解释主线排列，由当前 PR 决定，不要求固定编号或固定数量。章节之间用分隔线或明显留白区分，标题显著大于正文。
- 每节都应从上一节的落点继续讲；如果章节可以任意调换而不影响理解，说明页面可能只是在罗列信息，应重新组织。
- 当前 PR 的直接责任在视觉上高于关联背景；不要让关联功能的示例成为页面最大区块。必要的完成边界用小标签或一句话说明，不默认生成验证状态章节。
- 每节第一句给出直接结论，并说明它与上一节的关系；后续内容用于解释或核对。

## 归属与状态标签

- 当信息容易被误认成同一层时，可以使用简短的小标签，例如“能力来源”“当前 MR”“尚未验证”“不在本 MR”。标签按当前 PR 选择，不固定种类；不为了展示 CI、测试清单或合入条件而增加标签。
- 标签用较小字号和克制的边框或颜色显示，补充归属或状态，不代替正文。
- 当前 PR 的标签可以使用强调色；未完成或风险状态使用警示色；不能只靠颜色传达含义。

## 内容组件

按信息选择组件，不为了丰富而使用：

- **关系链 / 流程链**：适合展示因果、执行先后、依赖传播或工作阶段。每一步必须说明和下一步的关系，不能把事实并排列成装饰性的时间线。
- **修改前后表格**：只在当前 PR 直接改变可观察行为时使用。
- **状态并排卡片**：只在多个状态本身就是理解当前 PR 的主线时使用，例如分阶段迁移；不要用它展示普通测试与 CI 清单。
- **代码或配置卡片**：展示 reviewer 需要核对的真实配置、报错或关键 diff；顶部用小标签说明它在证明哪条结论。
- **职责或依赖示意**：只在职责移动或代码结构本身就是当前 PR 的主题时使用，突出职责移动和依赖方向，不平铺全部文件。

文件路径和 diff 要就地挂在它所证明的结论旁边，不单独生成 changed files 清单、目录树或 review map。

只用一种强调色和一种警示色。表格、卡片和折叠标题的字号不小于正文。

## 默认可见与折叠

- 默认可见内容必须能独立说明当前 PR 的角色、解释主线，以及改动为什么会产生所述结果；只有必要时才补一项完成边界。
- 用原生 `<details>` / `<summary>` 折叠核对依据，默认收起；点击、触摸和键盘都能展开。
- 折叠块使用边框与正文区分；标题写明里面是什么；展开后标题与内容之间有分隔线和内边距。
- 折叠只有一层，不嵌套折叠。

## HTML 实现

- 输出完整单文件 HTML，包含 DOCTYPE、`html`、`head`、`body`，设置简体中文语言、UTF-8 和 viewport。
- CSS 全部内嵌，不引用外部库、字体、图片或其他网络资源，也不发起网络请求。
- 除打印前展开全部 `<details>` 外不使用 JavaScript。JavaScript 未执行时，默认内容和折叠标题仍然可读。
- 桌面和移动端都可读，正文宽度适中；代码块横向滚动或换行，不撑破页面；支持浅色、深色模式和清晰的键盘焦点样式。
- 打印前展开所有 `<details>`，使完整内容进入打印结果。
- 不使用 iframe、表单、eval、Function 或动态加载脚本。
- 来自 PR、issue、源码和配置的文本一律进行 HTML 转义，不进入可执行上下文。
